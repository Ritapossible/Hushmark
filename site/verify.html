// Verify

Check a receipt yourself.

Every Hushmark review leaves a receipt with hashes only, never code. Paste one here and your browser checks it without trusting Hushmark: the receipt's ID, its nonce, the signature made inside the NEAR AI Cloud TEE, and the anchor on NEAR testnet. Nothing you paste leaves this page.

Where to find a receipt

  • On any pull request: open the Hushmark check, then Details. The receipt is the JSON block at the bottom; paste the whole text.
  • From the GitHub Action: the workflow artifact hushmark-receipt-pr<N> holds the receipt and its attestation report.
  • From an AI agent: the MCP server's review tool saves both under ~/.hushmark/receipts/.

What this page checks, and what it cannot

  • Receipt ID: the SHA-256 of the receipt's exact canonical bytes. Any edit changes it.
  • Nonce: recomputed from the review's key and salt, so the TEE evidence was made for this review and cannot be replayed from another.
  • Signature: the signed text must be model:sha256(request):sha256(response), and the signature must recover to the signing address written in the receipt. Any key can sign, so this alone does not prove a TEE.
  • NEAR anchor: the contract anchor.hushmark.testnet must hold this receipt's hash for this review's key. It accepts one receipt per key, so an anchored verdict cannot be swapped later. A /hushmark re-run makes a new receipt for the same key, which reads Not the anchored receipt.
  • Not in the browser: Intel's TDX quote and NVIDIA's GPU verdict, which prove the signing key lives in genuine hardware. That is why this page never says Verified: its best verdict is Signature matches; TEE not checked. Run hushmark-verify receipt.json attestation.json (from the repository) with the attestation report for the full verdict.

Same checks, same code path as the command and the MCP server's verify_receipt: receipt_check.py. Format: RECEIPT.md.
