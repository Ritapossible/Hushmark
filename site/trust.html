// Trust

How to trust a Hushmark result.

For security reviewers. What Hushmark proves, what it does not, where your code goes, and the code and tests behind every claim. Every link goes to the public source.

The claim, exactly

Hushmark's review code has no shell, so nothing in a pull request can make it run code. A finding is shown only if it was signed inside a NEAR AI Cloud TEE for that exact input. This is a claim about Hushmark's code, not about the machine it runs on.

What is proved

ClaimHowBacked by
Nothing in a pull request can make Hushmark run code.Hushmark never checks out the pull request; the diff, title and body arrive as text through the GitHub API. The review code cannot start a process: a lint rule bans every process API, and every test runs under an audit hook that fails on any process start, from the first import. The model is never given tools.pyproject.toml (banned APIs) · tests/conftest.py (audit hook) · tests/test_no_shell.py · tests/test_action.py test_workflow_never_checks_out_or_runs_the_pull_request · tests/test_recordings.py test_request_carries_no_tools
A finding is shown only if the model ran in an attested NEAR AI Cloud TEE, on exactly the request Hushmark sent.Checks a–f: Intel's TDX quote verified with dcap-qvl, the signing key and a fresh nonce bound into it, measurements replayed, NVIDIA's signed GPU verdict, and the TEE's signature over the exact request and response bytes. Any failure is a refusal and no model finding is shown.hushmark/verify/attestation.py · hushmark/verify/nras.py · hushmark/verify/signature.py · tests/test_attestation.py · tests/test_nras.py · tests/test_recordings.py (one changed byte, a swapped nonce, a removed attestation and a gateway signature are all refused)
Every finding points at a region Hushmark found itself.The model may only name a candidate ID from this run; the file and line always come from Hushmark's own scan. An unknown ID is dropped and counted, and an answer that breaks the schema refuses the run.hushmark/verify/grounding.py · tests/test_grounding.py (fixture 08)
Only excerpts leave GitHub, and only to an attested TEE.The model receives the hidden regions with up to ten lines of context, never the full diff, title or body. What is not proved

  • The host is not in a TEE. In v0.1 Hushmark runs on a GitHub Actions runner (or the App's server). It sees the full diff, as GitHub already does, and someone who compromised it could skip verification. The claim covers Hushmark's code, not the machine it runs on. Moving the service into a confidential VM is the first item on the roadmap.
  • TEE trust is hardware trust. It holds only if Intel TDX and NVIDIA confidential computing are sound.
  • Which software runs in the TEE is not pinned. The checks prove a genuine, up-to-date TDX machine with NVIDIA GPUs that holds the signing key and our nonce, with consistent measurements. They are not compared against values NEAR AI Cloud publishes, so "a NEAR AI Cloud TEE" rests on reaching its API over TLS. Pinning them is on the roadmap.
  • A receipt alone does not prove a TEE. Its signature only shows the key named in it signed it. Only hushmark-verify with the attestation report says Verified; the browser verifier never does.
  • Detection is not complete. Hidden instructions in forms the detectors do not know are missed, and plain visible instructions outside agent rules files are not flagged.
  • The model sees excerpts, not the whole change. It judges whether a hidden region is aimed at an agent, not what the pull request does.
  • Files in ignore are not reviewed. The check names every file it skipped.
  • Evidence is checked as of a moment. The browser verifier cannot check Intel's and NVIDIA's evidence; hushmark-verify checks them as of now, not as of the review.

Where your code goes

DataWhere it goes
Full diff, PR title and bodyRead through the GitHub API by Hushmark on GitHub's own runner (or the App's server). Never sent to the model, never logged, never stored.
Hidden regions, with up to ten lines of contextSent to the model inside the attested NEAR AI Cloud TEE. Nothing else is.
FindingsShown on the pull request's Hushmark check, visible to whoever can see the repository. A model's explanation has any link replaced by the word "link".
ReceiptHashes only: no code, no finding text, no repository name. Shown in the check's details and kept as a workflow artifact.
NEAR testnetTwo hashes: the review key's and the receipt's.
LogsIDs and reason codes only. A refusal says where a model answer broke, never what it said.

Who it defends against

AttackerDefence
Someone who opens a malicious pull request, including from a forkNothing is run. Hidden regions are found by fixed rules, so the model cannot hide one by saying nothing; an unverified run still shows them as unconfirmed.
The same person, trying to spend your creditNo model call without hidden regions; 20-region and 200-line caps; a daily review budget per repository.
The same person, trying to change the rulesConfiguration comes from the base commit only.
A replay of old evidenceA fresh nonce per review is bound into the TEE's evidence, and the signature covers the exact bytes.
An injected or hallucinating modelIt can only name candidates Hushmark found; links in its explanation are not rendered.
A forged webhook, or a stranger asking for a re-run (GitHub App)Every webhook's signature is checked first; /hushmark works only for admins and maintainers, never bots.

Check it yourself

  • A receipt: paste it at Verify, or run hushmark-verify receipt.json attestation.json for Intel's and NVIDIA's evidence too.
  • The whole test suite, offline, no key: git clone https://github.com/Ritapossible/Hushmark && cd Hushmark && make install && make verify. It replays real NEAR AI Cloud evidence byte for byte.
  • The contract: contract/README.md gives the account and the on-chain code hash, which matches the build.

Report a vulnerability

Use GitHub's private vulnerability reporting on the repository (Security → Report a vulnerability). Please do not open a public issue. See SECURITY.md.
